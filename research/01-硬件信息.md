## 屏幕与显示链路（关键）

这块屏**不是**普通 DSI 直连屏，中间隔了两颗 I²C 芯片：

```
SoC DSI0 ─┐
          ├─→ TI SN65DSI86（I²C 0x2C，DSI→eDP 桥）─→ PS8331 mux（I²C 0x33）─→ eDP OLED 面板
SoC DSI1 ─┘
```

| 项 | 值 |
|---|---|
| 面板类型 | **13 英寸 OLED**，2160 × 1350 @ 60 Hz |
| 接口 | eDP（面板侧），DSI（SoC 侧） |
| 双链路 | **bonded split 模式**，每条 DSI 链路承载 1080 × 1350（左右半屏） |
| 桥接 IC ① | **TI SN65DSI86** @ I²C `0x2C`（8-bit 写 0x58）——真正做 DSI→eDP 转换，接收 59 条初始化表 + TPS1 + 链路训练 |
| 桥接 IC ② | **PS8331 mux** @ I²C `0x33`（8-bit 写 0x66）——只做端口切换，仅 4 条寄存器 |
| 面板 DCS | **无**（NO DCS init sequence） |
| DSC 压缩 | **无** |
| 触控 IC | **Goodix GT738x** @ I²C13（`i2c@a94000`）地址 `0x5d`，reset 38 / report 25 / irq 39，供电 `vtouch`（pm8150_l16） |

> ⚠️ 两个易错点，研究时注意：
> 1. **桥其实是两颗芯片**。早期 38 轮排查一直把 DSI86 的 59 条初始化表写到 `0x33`（mux），
>    而真正的桥在 `0x2C`——写错芯片导致"寄存器全图 0 差异"是假象（B39 修正）。
> 2. **I²C 总线编号**：Android 侧是 `bus 5`，mainline 侧是 `bus 1`，芯片地址相同。

## 原厂 Android 是否能正常显示

**能，完全正常。** 设备日常就在跑原厂 Android，屏幕、触控、亮度全部正常，
说明**面板、桥、eDP 链路在硬件层面完好**。问题只出在"我们自己的内核把 DSI 流喂给桥"这一段。
