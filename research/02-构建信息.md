## 关键 CONFIG（实际生效值）

```
CONFIG_DRM_MSM=m                    # msm 整体编成模块（不上 builtin，见硬规矩）
CONFIG_DRM_MSM_DPU=y
CONFIG_DRM_MSM_DSI=y
CONFIG_DRM_PSA8331=m                # eDP 桥（DSI86 + PS8331 mux）驱动，模块
CONFIG_DRM_PANEL_LENOVO_K606F=y     # 面板驱动，builtin（技术债 #30：与"=m"规矩不符）
CONFIG_PSTORE=y
CONFIG_PSTORE_CONSOLE=y
CONFIG_PSTORE_RAM=y
CONFIG_PSTORE_PMSG=y
CONFIG_DEBUG_INFO=y                 # 产物偏大，发布时可关
```

> 注意：`CONFIG_PSTORE_FS` **在本内核里不存在**（Kconfig 无此符号，见 `03-当前现象.md` 的疑点一节）。

## 构建命令

```sh
SRC=$PWD/sources/pmos-sm8250 OUT=$PWD/out/kernel-msmmod \
  CFG=$PWD/sources/k606f-probe.config tools/build-kernel.sh Image modules dtbs
```

打启动镜像（只 `fastboot boot`，不写分区）：`tools/bringup.sh`，产物 `out/boot-probe.img`。

## 上机后必须做的两件事

1. **同步模块**：`out/kernel-msmmod` 里所有 `.ko` 拷到 `out/kmod-probe/`
   —— 否则 insmod 报 `invalid module format`（B40、B66 两轮因此作废）。
2. **核对 vermagic**：Image 的版本串与 `.ko` 的 vermagic 必须一致（`g4f90c5c9800d`）。

## 已知的构建纪律（踩过的坑）

- `tools/bringup.sh` 的默认 `SRC` 指向上游 `sources/linux-7.2`，**必须显式传 `SRC=`**，
  否则会静默用错源码树、丢掉板级 config（技术债 #22）。
- 不要同时跑两个 `build-kernel.sh` 写同一个 OUT（技术债 #14，flock 挡不住）。
- 新驱动一律 `=m` 手动 insmod，**不要 builtin**（技术债 #21：builtin probe 挂住会连 USB 调试通道一起死）。
